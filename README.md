# Moonlit Mooncake Match

请帮我从零开发一个移动端优先的中文网页小游戏。

项目名称暂定：

「你的中秋人格，藏在什么月饼里？」

这是一个以中秋节和东方月夜美学为主题的轻量级人格测试小游戏。

IMPORTANT：

这不是严肃的心理学测试，也不要使用“科学测评”“心理诊断”“人格诊断”等表达。

它是一款娱乐性质的中秋互动小游戏。

核心体验是：

“用户凭直觉回答 5 道问题 → 月亮记录答案 → 最后揭晓用户是哪一种月饼人格。”

整个产品应该让用户感觉：

“我本来只是想玩一下，结果月亮告诉我，我原来是一块这样的月饼。”

==================================================

一、整体产品定位

==================================================

目标用户：

喜欢小红书、年轻国风、视觉类互动内容的年轻用户。

使用场景：

用户在手机上打开一个小红书 Vibe Coding 小工具。

产品核心目标：

1. 第一眼有吸引力

2. 30 秒左右可以完成

3. 操作简单

4. 有“揭晓结果”的期待感

5. 结果页具有截图和分享价值

6. 用户完成后会产生“想让朋友也测一下”的冲动

核心关键词：

东方

中秋

月夜

月亮

桂花

月饼

温柔

高级

年轻国风

神秘

治愈

轻游戏

分享感

不要做成：

- 廉价传统节日模板

- 大量红色灯笼

- 大量金色祥云

- 电商月饼广告

- 普通心理测试网站

- 企业官网

- 复杂 SaaS

- 过度赛博朋克

- 过度卡通幼儿风

视觉方向应该是：

“现代东方美学 + 中秋月夜 + 年轻人的轻盈感”。

==================================================

二、技术与产品要求

==================================================

请优先开发一个完整可运行的前端产品。

要求：

- Mobile-first

- 同时兼容桌面端

- 中文 UI

- 页面响应式

- 操作流畅

- 不需要用户登录

- 不需要数据库

- 不需要注册

- 不需要复杂后端

- 所有测试逻辑在前端完成

- 用户刷新页面后可以重新开始

- 不需要保存用户个人信息

如果需要技术栈，请选择你最稳定、最适合快速开发和部署的现代前端方案。

代码需要保持结构清晰、组件化。

四、首页设计

==================================================

首页标题：

「你的中秋人格，

藏在什么月饼里？」

副标题：

「凭感觉选，别想太久。

月亮会替你揭晓答案。」

可以增加一行非常小的辅助信息：

「5 道题 · 约 30 秒」

主要 CTA：

「开始测试 →」

首页视觉：

一个非常大的、柔和的满月作为视觉中心。

背景是深蓝或月光蓝的夜空。

可以有：

- 少量星星

- 少量桂花

- 一枝淡淡的桂花枝

- 远处非常克制的东方屋檐轮廓

- 少量云雾

不要堆满元素。

要有大量留白。

月亮应该是首页最重要的视觉主体。

整体感觉：

安静、漂亮、有一点神秘。

打开首页时可以有非常轻微的动画：

月亮缓缓升起

→ 少量桂花飘落

→ 标题淡入

→ CTA 出现

动画必须克制、流畅，不要花哨。

五、测试页整体设计

==================================================

测试页面不要做成普通问卷。

不要使用：

“第 1 题 / 5”

而是使用“月相进度”。

例如：

Q1：

🌑 ○ ○ ○ ○

Q2：

🌒 ○ ○ ○ ○

Q3：

🌓 ○ ○ ○ ○

Q4：

🌔 ○ ○ ○ ○

Q5：

🌕

可以设计成非常简洁的月相进度指示器。

顶部可以显示：

「今夜的月亮正在听」

题目位于页面中央。

选项使用大尺寸圆角卡片。

卡片：

- 半透明

- 深色背景

- 轻微边框

- 柔和阴影

- 足够大的点击区域

用户点击选项以后：

- 卡片出现月光高亮

- 有非常轻微的缩放/淡入效果

- 然后自动进入下一题

不要再让用户点击“下一题”。

==================================================

十五、平分判定规则

==================================================

首先计算六种人格的总分。

总分最高者为最终结果。

如果出现并列，不要随机选择。

使用以下隐藏优先级：

Q5 > Q4 > Q2 > Q3 > Q1

也就是说：

1. 先比较总分

2. 如果并列，比较这些并列结果在 Q5 用户所选答案中的得分

3. 如果仍然并列，比较 Q4

4. 如果仍然并列，比较 Q2

5. 如果仍然并列，比较 Q3

6. 如果仍然并列，比较 Q1

最终必须得到唯一结果。

不要使用随机数解决平分。

大量留白。

不要让所有东西都发光。

不要使用过度渐变。

不要使用廉价的 3D 金色效果。

==================================================

十八、响应式设计

==================================================

这个产品首先是手机网页。

重点适配：

390 × 844

375 × 812

430 × 932

同时兼容桌面。

手机端：

- 题目不要过小

- 选项点击区域足够大

- 不要出现横向滚动

- 重要内容尽量在首屏

- 结果卡片适合截图

桌面端可以限制内容最大宽度，使其仍然像一个精致的移动小游戏，而不是铺满整个宽屏。

==================================================

十九、交互细节

==================================================

所有点击都应该有反馈。

选项点击：

轻微缩放

→ 月光高亮

→ 自动进入下一题

不要有明显的 loading。

页面切换应该有：

淡入

轻微上移

或月光扩散效果。

不要使用：

- 大量弹窗

- 浏览器 alert

- 复杂菜单

- 登录

- 注册

- 广告

==================================================

二十、重要产品原则

==================================================

1. 用户不能在测试过程中轻易猜出自己对应的月饼。

2. 不要在问题旁边解释：

“这个问题是在测试你的感受力。”

3. 不要告诉用户：

“A 代表桂花莲蓉月饼。”

4. 不要出现任何科学心理测量的措辞。

5. 六种人格没有高低之分。

6. 每种人格都必须写得让人喜欢，而不是出现“缺点人格”。

7. 结果必须有“原来如此”的感觉。

8. 产品应该有一点“盲盒揭晓”的感觉。

9. 页面视觉优先级高于复杂功能。

10. 整体体验应该在 30 秒左右完成。
